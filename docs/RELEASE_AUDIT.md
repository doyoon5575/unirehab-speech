# 출시 점검 — 2026-10-14

## 결론
현재는 로컬 프로토타입입니다. 이 브랜치는 일부 보완이며 정식 출시 인증이나 임상 검증을 의미하지 않습니다. 실환자 데이터 입력 및 공개 운영을 권장하지 않습니다.

## 확인한 출시 차단 요인
- store.js: 환자 정보/진단/회기/백업은 평문 JSON. 기존 README의 암호화 주장은 사실과 다릅니다.
- 계정 인증, 서버 저장, 치료사별/기관별 접근 통제가 없습니다. 로그인 UI만 추가하는 것은 해결책이 아닙니다.
- 짧은 시간 기반 환자/회기 ID는 충돌 가능. UUID로 전환하고 기존 참조를 유지해야 합니다.
- 초기 가상환자/가상회기와 실사용 데이터의 분리 필요.
- 백업 입력의 스키마/크기/참조 검증 및 원자적 복원 필요.
- 임상 오류 분류, 난이도 조정, SOAP은 전문가 검토 대상입니다. 타당화된 진단 도구로 홍보하면 안 됩니다.
- 브라우저 STT 사용 시 외부 처리 가능성 안내 및 동의/철회 흐름 필요.

## 이번 브랜치 수정
- 0바이트 naming-prompt.mp3 대신 기존 nam-01.mp3 경로를 이름대기 안내에 사용. 실제 녹음 내용/청감 일치는 출시 전 확인 필요.
- 음성 종료/실패의 중복 callback 및 취소 후 오래된 fallback 차단, 재생 시 pitch 보존.
- 환자 전환/페이지 이탈 시 마이크와 음성 정리.
- 서비스워커는 동일 출처 공개 자산만 캐시. API/로그인/사용자 자료는 제외.
- 개발 서버 공개 파일 allowlist, 실경로 확인, 메서드 제한, 보안 헤더, localhost 기본 바인딩.

## 권장 출시 구조
- 체험: 가상 자료 전용, 로그인 불필요.
- 임상 사용: 검증된 인증 서비스의 이메일 인증/비밀번호 재설정/세션 만료/로그아웃, 기관 관리자 MFA.
- DB: 기관/치료사/환자/회기 분리, 서버에서 소유권 검증, 최소권한 접근 정책 및 접근 감사기록.
- 기존 localStorage는 인증 연동만으로 안전해지지 않습니다. 실데이터 쓰기 경로를 서버 기반으로 교체하고 기존 자료의 동의 기반 마이그레이션을 구현해야 합니다.
- HTTPS, 운영/개발 환경 분리, 비밀키 서버 보관, 백업 복원 훈련, 장애 모니터링.
- 보관기간/삭제/동의/외부 음성처리/사고 대응 정책과 전문 법률·임상 검토.

## 음성 품질
MP3 존재는 사람 같은 음성의 증거가 아닙니다. 96문항 음원과 동적 단서/피드백을 한국어 언어재활사가 청취 검수해야 합니다. 동적 문장은 현재 브라우저 합성이므로 기기마다 품질이 달라집니다. 통일된 자연스러운 음성을 원하면 고정 문장을 검수된 음원으로 추가하거나 인증/할당량/비용 제한을 갖춘 서버 TTS를 구축해야 합니다. 개인식별·임상 정보를 TTS 공급자에게 전송하지 않는 설계가 우선입니다.
